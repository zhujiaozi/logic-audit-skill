# Logic Audit Skill · 逻辑审计

[![License](https://img.shields.io/badge/License-MIT-111111?style=flat-square)](LICENSE)
[![Skill](https://img.shields.io/badge/Skill-Agent-111111?style=flat-square)](SKILL.md)
[![Claude Code](https://img.shields.io/badge/Claude%20Code-Supported-6B5B95?style=flat-square)](https://claude.ai)

一个适配 Claude Code / Codex 等 Agent 环境的逻辑审计技能，用于对论证、判断、决策、分析或推理材料进行**系统性深度审查**。

v3.3 在原有“逻辑漏洞检测”的基础上，补强了：

- 顶部硬规则（不得伪造 / 不得把待验证前提当事实 / 结论强度不得超过证据等级等）
- 事实核查边界声明
- 证据等级 E0-E5
- 关键前提缺失时的澄清机制
- 对抗性审查：反例、替代解释、边界条件
- 发布前自审：审计你自己的审计，防造数字、防误报、防越权重构
- 每条发现带确信度（高/中/低）与证据基础（直接/推断/旁证）
- 谬误速查按 4 大家族归类（相关性 / 弱归纳 / 非法预设 / 形式谬误），便于逐族扫描
- 严重度校准防通胀：信息缺失归核查清单而非判 🟡，作者已克制的表述不重复扣分
- 产品/技术/商业/学术/数学/代码等领域审查清单
- 大材料覆盖策略
- 结论可靠性分级
- 可公开的修正论证链，避免过度脑补

> 由 [归藏](https://x.com/op7418) 的 guizang-ppt-skill 启发，沉淀于日常逻辑训练场景。

## 什么时候用

### 适合触发

- “帮我审计这段推理”
- “检查逻辑漏洞”
- “查一下有没有逻辑错误”
- “修正这个思考链”
- “帮我找反例”
- “这个产品/技术决策有没有问题”
- 用户给出了带编号或不带编号的多步推理、论证、因果分析、数学推导、决策链

### 不需要触发

- 日常对话、单步问答
- 无显式或隐含论证结构的简单请求
- 只需要改写、润色、总结，而非检查逻辑
- 主要输入是日志、代码文件或事实材料本身，而不是围绕它们的论证

## 检测能力一览

技能覆盖常见逻辑问题，并为每条发现标注严重度：

| 🔴 严重 | 🟡 可疑 | ⚪ 轻微 |
|---------|---------|---------|
| 足以推翻结论或使结论高度不可靠 | 显著降低可靠性，但未必直接推翻 | 表述、边界或严谨性问题 |

| # | 类别 | 简要说明 |
|---|------|---------|
| 1 | 前提真实性 | 虚假前提、无依据断言、隐藏假设 |
| 2 | 步骤完整性 | 跳过必要推导环节 |
| 3 | 因果混淆 | 相关 ≠ 因果、方向倒置、忽略混杂变量 |
| 4 | 循环论证 | 结论隐含在前提中 |
| 5 | 数值/计算错误 | 算术、统计、概率、百分点/百分比混淆 |
| 6 | 以偏概全 | 小样本推普遍结论 |
| 7 | 非黑即白 | 忽略中间或替代选项 |
| 8 | 稻草人谬误 | 歪曲对方观点后攻击 |
| 9 | 诉诸情感/权威 | 情感渲染或无关权威代替论证 |
| 10 | 滑坡谬误 | 无充分证据的连锁极端后果 |
| 11 | 偷换概念 | 关键词在不同步骤中含义漂移 |
| 12 | 诉诸自然 | 将“自然”等同于“正确/安全” |
| 13 | 合成/分割谬误 | 部分属性推整体，或整体属性推部分 |
| 14 | 证据强度不足 | 结论强度超过证据等级 |
| 15 | 替代解释遗漏 | 忽略同样合理或更简单的解释 |
| 16 | 价值/事实混淆 | 将事实判断直接推出价值或规范结论 |
| 17 | 指标替代 | 用单一指标替代整体判断 |

## 证据等级

当论证依赖事实或外部资料时，skill 会标记证据强度：

| 等级 | 含义 |
|---|---|
| E0 | 未给证据，仅有断言、直觉、传闻 |
| E1 | 个案或个人经验 |
| E2 | 非系统观察，小样本或未控制变量 |
| E3 | 相关性证据，有数据但因果未确认 |
| E4 | 有控制的研究/实验 |
| E5 | 多来源一致证据，如系统综述、元分析、可复现实验或权威统计 |

默认只做逻辑审计，不等同于联网事实核查。未核查的现实断言会标记为“待核查”。

## 输出样例

```text
### 输入类型与审计范围
- 类型：产品/技术决策 + 因果归因
- 范围：基于用户提供文本的逻辑审计；未进行外部事实核查。

### 重构后的论证结构
1. [原文] A 指标下降。
2. [重构] A 指标下降主要由 B 原因导致。
3. [原文] 因此应立即采用 C 方案。

### 审计报告
- **步骤 2** | 🟡 因果归因过强 | 确信度 中（据 推断） — 目前只说明 A 与 B 同时出现，未排除季节性、渠道变化等混杂变量。
- **步骤 3** | 🔴 替代方案遗漏 | 确信度 高（据 直接） — 从“B 可能有影响”直接跳到“立即采用 C”，缺少与 D/E 方案的成本收益比较。

### 证据与事实核查清单
- [待核查] A 指标下降的真实幅度、时间窗口和统计口径。
- [E0] B 是主因：当前未给证据。

### 对抗性检查
- 最小反例：如果同期渠道流量质量下降，A 指标下降可能与 B 无关。
- 替代解释：季节性、样本变化、埋点变更、竞品活动。
- 边界条件：C 方案只在 B 被验证为主要瓶颈时更有说服力。

### 修正后的可公开论证链
1. 观察到 A 指标在某时间窗口下降。
2. B 是一个可能原因，但需与其他因素共同排查。
3. 若数据验证 B 对 A 的影响最大，且 C 方案成本可控，则可优先小范围试验 C。
4. 在实验结果证明有效后，再考虑扩大推广。

### 结论可靠性
- 等级：低到中
- 更稳妥表述：C 方案值得作为候选方案测试，但当前证据不足以支持“立即全面采用”。

### 自审确认
- 已核查/未核查事实如实区分；无编造数字或引用；已对每条问题做善意解读复核（防误报）。
```

## 评估测试

技能附带评估用例（`evals/evals.json`，当前共 32 条），覆盖：

- 因果混淆 + 以偏概全 + 非黑即白
- 基本正确推理
- 过短输入
- 数值计算错误与百分点/百分比混淆
- 只有结论没有理由
- 产品决策中目标/约束缺失
- AI 生成内容的虚构引用风险
- 数学推导中的必要/充分条件混淆
- 学术论证：小样本、相关≠因果、超范围外推
- 政策判断：事实 / 价值 / 规范性结论三层分离
- clean case：误报控制（结论已恰当限定时不得过度挑错）

这样可以保证技能在新增能力时仍保持可验证、可回归、可维护。
